# Maximum gzip bytes of first-load JavaScript on a point page
# (`/[locale]/[location]`), checked by `nix run .#size` (scripts/bundle-budget.ts).
#
# The visitor this page is designed for is on mobile data in the middle of an
# emergency, so this is the one number worth gating. The quote form posts
# without any of it — the budget is for what the page costs to become
# interactive, not for whether it works.
#
# Measured: 215,355 B gz (733.6 KB raw), Next 16.3.6 / Turbopack, uikit 0.19.0,
# marketing 0.2.0 — down from 227,085 once the error and not-found screens
# (the whole copy of both languages) stopped riding in every page's first load.
# Ceiling set ~4.5% above so ordinary churn does not trip it and a real
# regression does. By chunk, identified by what each one contains:
#   ~71.6 KB  react-dom
#   ~44.3 KB  the Next app-router runtime
#   ~42.9 KB  the uikit's client components — one barrel, all of it
#   ~30.5 KB  `@evinvest/marketing/react`: ContactLinkTracker, and motion with it
#   ~21 KB    the rest: Turbopack runtime, route chunks, the analytics island
# For comparison, the Dioxus build this replaces shipped 1,168,203 B of
# uncompressed wasm; the equivalent raw figure here is ~730 KB.
#
# Raising this is a deliberate commit with a reason in the message, never a
# silent edit. The next levers are in the lib (EV-invest/lib, perf/landing-weight):
# per-module uikit with a named-export barrel, so a server-rendered `Button`
# does not bring the kit's client half along, and `@evinvest/marketing/tracker`
# without motion — measured together at ~150 KB gz on this page.
225000
